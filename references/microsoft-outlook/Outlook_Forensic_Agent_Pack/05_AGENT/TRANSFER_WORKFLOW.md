# Agent production workflow — transfer without imitation
## Stage 1: discovery
Define audience, product promise, conversion action, trust signals, emotional targets and context. Example for Cause (artisan employment marketplace): reduce friction between a qualified person and a real opportunity; create confidence, dignity, craft and connection. Do not assume original Outlook objects or palette belong to Cause. Use authentic South African context and approved interface copy; Sipho Dlamini is the selected example name if appropriate. Do not invent product claims, verified credentials or brand colours. User-provided brand rules override hypothetical examples.
## Stage 2: responsibilities before vocabulary
Define each visual role: stable ground, connecting infrastructure, focal interface, human identity, evidence of skill, tactile contrast, controlled irregularity, expressive accent, optical boundary, transition metaphor, scale reference. Derive several candidate objects for each role, compare their geometry, material, semantic association, readability and cultural relevance. Select the smallest coherent library. An engineered tool tray, machined material sample, measuring instrument, fastener, work order, certificate or architectural plan could be valid candidates only if justified by a role. Do not simply surround a dashboard with floating tools. Keep human identity meaningful, not decorative.
## Stage 3: architecture and storyboard
Plan a shared visual language with local clusters and protected information zones. Establish six scales and offscreen continuation. Plan sequence using anticipation → spectacle → discovery → concentration → comprehension → resolution as recurring modes, not mandatory order. For conversion, open with product-relevant tension or benefit, demonstrate a believable flow (search, match, application or booking as appropriate to actual product), conclude with clear action. Tie every shot to an audience question. Use actual UI states where available. Preserve flexibility to compose separate worlds with consistent design language.
## Stage 4: geometry, materials and optical direction
Specify stable object IDs, parent relationships, local origin, intended dimensions, shapes and surface finish. Distinguish geometry vs texture vs embedded image. Define material roles, roughness ranges as hypotheses, lighting direction, shadow class, optical relationships, and microdetail visibility. Build true thickness, bevels, cavity, curved paths and occlusion when needed. Do not recover original 3D coordinates from projected bounds. For new brand, choose palette after purpose and contrast tests. Use rendered colour sampling for match, not direct albedo assignment.
## Stage 5: camera and motion
Design camera and object tracks separately. For each event, define trigger, start/end state, timing, dependencies, path, easing hypothesis, hold, focus and visibility. Coordinate motion budget across regions. Structural movement restrained; expressive animation may overshoot selectively. Reveal geometry then information when useful; allow responsive content layout without bitmap scaling. Use motion to clarify meaning (completion, reordering, matching) instead of arbitrary floating. Stabilise during reading. Use existing geometry for portal/occlusion transitions if narrative warrants.
## Stage 6: implementation choice
Choose Blender/offline render for complex optical interactions and precision product rendering; real-time Three.js for interactive/procedural delivery when appropriate. Neither is mandated by the reference. For Three.js, physically based materials, swept curves, subdivided deformable meshes, separate text/texture elements, scene graph and timestamp-driven state machine are candidate tools. Confirm colour management, shadows, transmission limitations, performance and text rendering. For Blender use calibrated cameras, material nodes and independent animation channels; match reference with controlled A/B comparisons if reconstructing. No renderer settings asserted as recovered. Keep reusable source assets editable and versioned. Avoid approximations that flatten the world without clearly reporting limitations.
## Stage 7: validation and iteration
First validate layout silhouette and scale. Then material/shadow/focus. Then motion and content. Then complete scene rhythm and conversion narrative. Compare reference frames when doing fidelity exercises; when doing original creative transfer, evaluate role equivalence and aesthetic quality without demanding pixel similarity. Critique the weakest system, modify one variable at a time and preserve regression checks. Use QA gates and evidence audit; mark every unmet requirement. Do not self-certify 95% rendering based on research. Provide outputs, source/project files, frame contact sheet, motion preview, limitations and change log when building.
